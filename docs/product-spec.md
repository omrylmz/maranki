## 0. The whole plan on one page

Maranki has one root problem with three faces:

1. **The importer throws data away, so filters had to be faked.** Real decks keep their level in a field (`Level`) and in the subdeck path (`German::Verbs::B1`). The importer keeps only front, back, one example and flat tags. It drops reverse cards, the Anki id (`guid`), study progress and images. So no screen *could* filter by level. The project then patched the screens four times and finally forked the app.
2. **One job is spread over many places, and about 15 controls are fake.** Home, Study and Progress all start sessions. "Create a deck" ends in a dead end. Restore, reminders, help, history export, typing mode and more only show a snackbar.
3. **Storage is fragile.** The whole library is one JSON string in AsyncStorage (2.9 MB for German_Complete; Android reads about 2 MB per value). There is no schema version, but the public v2.0.2 APK stored `word`/`tr` cards under the same key, so an update would crash.

The fix, in six ideas:

| # | Idea | What the learner gets |
|---|---|---|
| A | **Keep everything, derive everything else.** Store note fields (raw), tags, section, `guid`, templates, progress and images. Card text, filter groups, counts and search text are computed. | German: a Level filter with 100% coverage. Coding: Category + tag tree. No language code in the engine. |
| B | **One filter language.** One flat `Query` drives Library chips, saved Lists, every "Study N" number and every session. A filter group with no data in scope does not exist. | Counts always agree. No hidden scope. "Save as list" and "Study 34" work on any filter. |
| C | **"Not started" and "Known" are real states.** | The Vocabeo job comes back: "I know these A1 words", "teach me only B1 verbs". |
| D | **One place per job.** 4 tabs: **Today** (do), **Library** (find, choose, manage), **Progress** (look), **Settings**. Each deck gets a **deck page** (the hub). | No more "which tab is the study tab?". |
| E | **No fake controls.** Every stub is built for real on-device, or removed with a written reason. | Every button can be trusted. |
| F | **One codebase.** German = a build variant + a content pack (`APP_VARIANT=german`), about 100 lines plus 3 asset files. | Fixes land once. The fork is archived. |

**Delivery** is 6 waves (§10). Waves 0–2 change no screens except a crash screen and real backup/restore. They make data safe first (migration, testable store, storage that can hold 16k cards). Wave 3 switches the data to notes and makes import lossless. Wave 4 ships the new screens and all real controls. Wave 5 folds German back in and locks the rules with guard tests.

## 1. Product statement and glossary

### 1.1 Product statement

> **Maranki is a private, offline flashcard app for anything you want to remember.** Bring decks from Anki (`.apkg`, AnkiWeb) or a spreadsheet (`.csv`), or type your own. Maranki keeps every field, both directions and your Anki progress. It finds the filters that your data already has (level, type, category, section, tags), so you can **choose what to learn**, study a slice in one tap, and trust that **every number on a button is exactly the session it opens**. A build variant adds a starter pack (German) without a second app.

Non-goals (this program): cloud sync, accounts, AnkiWeb upload, FSRS scheduler, iOS store release, audio playback, Anki's newest export format (`collection.anki21b`). Each has a reason in §7 or §12.

### 1.2 Glossary — one meaning per word

The glossary lives in code at `src/content/glossary.ts`. The Help screen and every "?" InfoSheet read it, so the UI and Help never disagree. **UI words** are what users see. **Code words** are names in TypeScript.

| UI word | Code word | Meaning (exactly one) |
|---|---|---|
| **Deck** | `Deck` | A container of cards that you own. Every card is in exactly one deck. |
| **Section** | `Note.section` | A part of a deck that came from an Anki subdeck, for example "Verbs › B1". It is a filter, not a place with its own settings. |
| **Card** | `Card` | One thing you study, with its own schedule. |
| **Direction** | `TemplateDef` / `Card.ord` | Which side is the question. "German → English" and "English → German" are two directions of the same information. |
| (not shown) | `Note` | The information you enter once (field values, tags, section). A note has one card per enabled direction. **The UI never says "note".** When it must count notes it says "{n} items"; most screens avoid the noun ("Learn all 486 left"). |
| **Card type** | `NoteType` | The list of fields and directions shared by many cards, for example "German Verbs". |
| **Field** | `FieldDef` + `Note.fields[i]` | One named piece of information, for example "Level" or "Conjugation". |
| **Filter** | one group in `Query` | A removable chip that narrows a card list, for example "Level: B1, B2 ×". |
| **Filter group** | `Facet` | The values of one filter that exist in your data, with counts, for example "Level: A1 (581) · A2 (520)". |
| **List** | `ListDef` | A saved filter, like "B1 verbs". It is always up to date. It is not a folder: one card can match many lists. (Replaces "Collection".) |
| **Not started** | `Card.newState === 'notStarted'` | The card is in a deck but not in your study queue. Study never shows it until you choose it. |
| **New** | `reps === 0`, `newState !== 'notStarted'` | In your queue, waiting for its first study. Study brings in a few each day. |
| **Learning** | `stepIndex !== null` | Seen recently. Comes back in minutes. |
| **Review** | graduated, interval < 21 days | Comes back in days. |
| **Mastered** | graduated, interval ≥ 21 days, not Known | Long-term memory. |
| **Known** | `knownAt != null` | You said you already know it. It is not studied. A few Known cards come back once for a **Check**. |
| **Check** | spot-check bucket | One quick test of a Known card, to make sure. If you miss it, the card moves to Learning. |
| **Due** | `isDueNow()` | A Learning/Review/Mastered card whose time has come. A separate filter, not a status. |
| **Ready** | `ReadyCounts.total` | Learning + due reviews + checks + today's new cards, inside your daily limits and session size. **This is the number on every Study button.** |
| **Study** | session kind `scheduled` | The normal session. **It changes the schedule.** |
| **Study ahead** | kind `ahead` | Reviews that are not due yet, soonest first. It changes the schedule. |
| **Practice** | kind `practice` | Free practice. **It never changes the schedule or your daily counts.** (Replaces "Cram" and "Review hardest".) |
| **Choose what to learn** | `/triage` | Sorting Not started cards into Learn / I know it / Later. |
| **Daily goal** | `person.goalReviews/goalNew` | A target for the bars on Today. **It never blocks cards.** |
| **Daily limit** | `srs.dailyNewLimit/dailyReviewLimit` | The most new cards / reviews Study gives you per day. |
| **Session size** | `settings.sessionLimit` | The most cards in one session. Applies to **every** session. |
| **Bury** | `buriedUntil` | Hide a card until tomorrow. |
| **Suspend** | `suspended` | Hide a card until you unsuspend it. |
| **Favorite / Flag** | `fav` / `flagged` | Your own markers. They never change the schedule. |
| **Pause a deck** | `Deck.active === false` | The deck's cards leave Today. You can still study it from its deck page. |
| **Hint** | `hints.ts` | Shows part of the answer before you reveal it. |
| **Streak / Freeze** | `person.streak/freezes` | Days in a row you studied. A freeze saves one missed day. |
| **Backup** | `maranki-backup` file | One file with all your decks, cards, progress and settings. |

## 3. Data model, migration and storage

### 3.1 Schema versions

| Version | Where it exists | Shape | How `detectVersion` finds it (no `schemaVersion` field) |
|---|---|---|---|
| **0** | v2.0.0–v2.0.2 APK (`com.omrylmz.maranki`), German fork (`com.omrylmz.marankide`) | Card `{word, article, base, tr, ipa, ex, exTr, level, type, lang}`, Deck `{flag, lang, level, builtin}`, settings `{ttsEnabled, autoPlayAudio, pronunciationPrompt}`. v2.0.x markers have no `studyDay`; the fork's markers do. | Any card has a string `word` and no string `front`; **or** (no cards) a deck has `flag` and no `icon`; **or** `settings.ttsEnabled` is a boolean and `readAloudEnabled` is missing. |
| **1** | main@1333d48 dev builds | Card `{front, back, example?, notes?}`, Deck `{icon, builtin}`, `readAloudEnabled` | Every other document without `schemaVersion`. |
| **2** | Wave 1 (release v2.1.0) | v1 + `schemaVersion`, `minReaderVersion`, raw `legacy` copies, `autoReadAloud`. | `schemaVersion === 2` |
| **3** | Wave 3 (first shipped in v3.0.0) | Note model (§3.4). | `schemaVersion === 3` |
| **4** | "Contract" release, at least 2 releases after v3 | Drops `Card.legacy`, `Deck.legacy`, `collections`, `Deck.builtin`. | `schemaVersion === 4`, `minReaderVersion: 4` |

**Rules (all waves).**
1. Every stored shape change bumps `schemaVersion`. Additive changes keep `minReaderVersion`. Removing a field or changing its meaning raises `minReaderVersion`, and only 2 releases after the additive step.
2. Each step is a pure function `vN → vN+1` in `src/store/migrate.ts`. Steps are chained, idempotent and tested on real fixtures (§10, W0-1).
3. **Never destroy the source.** Before a version jump, the raw document is written once to `Paths.document/backups/premigrate-v{from}-to-v{to}-{stamp}.json` (keep the newest 3). Storage moves copy forward and leave the old copy for 2 releases.
4. **Repair, never drop.** Bad numbers get safe defaults. Orphans go to "Unfiled cards". The repairs are counted.
5. **Restore uses the same `migrate()`.** So every backup ever made restores, including v0 backups.
6. **A newer document is never misread.** If `schemaVersion > CURRENT` and `minReaderVersion > CURRENT` → outcome `too-new`: writes are blocked like C1, and the app says "This data was saved by a newer version of Maranki. Please update the app. Nothing was changed." If `minReaderVersion <= CURRENT`, the document is read as-is and keeps its higher `schemaVersion` (never downgraded; unknown fields survive because every reducer spreads objects).
7. **If `migrate()` throws, it is a read error, never "corrupt".** Writes are blocked (C1). The DataProblemScreen (§3.10) offers "Save a copy of the raw data". The seed is never written over intact data.

### 3.2 `migrate()` API (`src/store/migrate.ts`, pure)

```ts
export const CURRENT_SCHEMA = 3;          // 2 in wave 1–2, 3 from wave 3
export const MIN_READER = 3;              // 2 in wave 1–2

export type MigrateOutcome =
  | { kind: 'ok'; state: DataState; from: number; repaired: string[] }
  | { kind: 'too-new'; version: number }
  | { kind: 'invalid' };                  // not a Maranki document

export function detectVersion(doc: Record<string, unknown>): number;   // 0 | 1 | doc.schemaVersion
export function migrate(doc: unknown, now: number): MigrateOutcome;   // may THROW on a bug → caller treats as read error
export function v0toV2(doc: LegacyV0Doc, now: number): DataStateV2;   // lossless (legacy copies)
export function v1toV2(doc: LegacyV1Doc, now: number): DataStateV2;
export function v2toV3(doc: DataStateV2, now: number): DataStateV3;   // lives in src/store/migrateV3.ts
export function sanitize(s: DataState, now: number): { state: DataState; repaired: string[] };
export function mergeDefaults(s: DataState, now: number): DataState;
```

`migrate()` order: `invalid` check → `too-new` check → `v0toV2` / `v1toV2` → `v2toV3` (from wave 3) → `checkIntegrity` (v3) → `sanitize` → `mergeDefaults` → set `schemaVersion = max(from, CURRENT)` and `minReaderVersion = MIN_READER`.

**v1 → v2:** `sanitize` + `mergeDefaults`, `reminderEnabled = false`, `autoReadAloud = false`, `reminderTime` `'21:00'` → `'20:00'` (wave 5b, see the table).

**`sanitize` (repairs, never drops):** non-string `front/back` → `String(x ?? '')`; non-finite `ease` → `startingEase`, and `ease < 1.3` → `1.3`; non-finite `intervalDays/reps/lapses` → `0`; negative `reps/lapses` → `0`; non-finite `due` → `now`; a `stepIndex` that is neither `null` nor a non-negative integer → `0` when `reps > 0` (the card stays in learning; `srs.ts` clamps the range), else `null`; card whose `deckId` has no deck → moved to the Unfiled deck (`unfiledDeck()` from `deckOps.ts`) — **keeps the no-orphan invariant**.

**`mergeDefaults`:** deep-merge `settings` over `DEFAULT_APP_SETTINGS` and `settings.srs` over `DEFAULT_SRS`; `person` over the seed person (and `person.dayDone` over a zero day); missing arrays → `[]`; missing `inProgressSession` → `null`; missing `onboarded` → `cards.length > 0`. **A missing field can never become `undefined` in SRS math** (report 5: `undefined` → `NaN` due dates).

- **`front`/`back` are gone from `Card`.** Text is rendered from the note by `renderFace` (§6.2). The wave-1 "read seam" (W1-5) moves every reader to `useFaces()` first, so the wave-3 swap changes only the seam.

**`checkIntegrity(state)` (v3, `src/store/checkIntegrity.ts`)** returns `{state, repaired: string[]}`:
- card whose note is missing → kept out of `state.cards`; **the row store never deletes a row it did not load**, so the row survives on disk;

- cards of one note in different decks → all take the deck of the lowest-ord card;
- card whose deck is missing → Unfiled deck;
- note whose NoteType is missing → a "Recovered" NoteType with `Field 1…N` (role `detail`, first field `term`);
- duplicate `(noteId, ord)` → keep the first;
- `fields.length` ≠ type fields → pad with `''` / keep extra values in a "Recovered" field.
If anything was repaired, Today shows once: "We fixed {n} items in your library."

**`rateCard` rules** (`src/store/reducer.ts`, keeps every tally invariant):
- `writesSchedule(kind) = !(kind === 'practice' || kind === 'cram')`. If false: return `prev` except a calendar roll-over of `dayDone` (**H3**).
- Bucket: `card.knownAt != null` → `'check'`; `reps === 0` → `'new'`; else `'review'`.
- `'new'`: `applyRating`; tally `neww + 1` and `newByDeck[deckId] + 1` only (**M3**).
- `'review'`: `applyRating`; tally `reviews + 1`.
- `'check'`: Good/Easy → `knownCheckedAt = now` (stays Known; SRS untouched). Again/Hard → `knownAt = null`, `knownCheckedAt = null`, then `applyRating` from a learning start (`stepIndex 0`, keep `reps`, `lapses + 1` if `reps > 0`). Tally `checks + 1`.
- Append a `ReviewLogEntry` (bucket, prev snapshot, `seq = last + 1`), cap 400. Return the rated card (the session passes it as `finalCard`, **M6**).
- `undoLastReview`: pop the last entry, restore `prev`, untally its bucket (`newByDeck` too), never below zero.

**`ManualEdit` undo rule:** for each card, revert to `before` **only if** the card's current values still equal `after` on those keys. Otherwise skip it. Snackbar after a partial undo: "Undone for {r} cards. {s} were studied since and were not changed back." A manual edit **never** touches `reviewLog`, so session undo always undoes the last rating.

### 3.7 Storage: three stages

| Stage | Wave | Backend | Unit of write | Atomicity |
|---|---|---|---|---|
| Today | — | AsyncStorage, key `maranki.state.v1`, one JSON | whole JSON (2.9 MB German_Complete) | one `setItem` |
| **Stopgap** | 2 | `expo-sqlite/kv-store`: `new SQLiteStorage('maranki-kv.db')`, key `maranki.state` | whole JSON | one `setItemAsync` (kv-store wraps it in an exclusive transaction) |
| **Row store** | 3 | expo-sqlite tables in **`maranki-rows.db`** (its own file and connection, separate from the kv file, so an exclusive save never meets "database is locked") | only changed rows | one `withExclusiveTransactionAsync` per save |

The kv-store stopgap ships in wave 2 because it **removes the ~2 MB Android read limit and the 6 MB AsyncStorage cap with a tiny change**, before the bigger row store. Theme preference also moves to the kv file (`getItemSync` → no first-frame wait).

**Web.** `withExclusiveTransactionAsync` throws on web (`node_modules/expo-sqlite/src/SQLiteDatabase.ts:179`). Web is a **dev preview only**: `createStoragePort()` returns an in-memory port on web, and a quiet banner says "Web preview — nothing is saved." (Decision D6.)

```sql
  seq INTEGER PRIMARY KEY, card_id TEXT NOT NULL, deck_id TEXT NOT NULL, at_ms INTEGER NOT NULL,
  rating TEXT NOT NULL, bucket TEXT NOT NULL, ivl_before REAL NOT NULL, ivl_after REAL NOT NULL,
  ease_after REAL NOT NULL, duration_ms INTEGER);
CREATE INDEX IF NOT EXISTS revlog_card ON revlog(card_id);
CREATE INDEX IF NOT EXISTS revlog_at ON revlog(at_ms);
PRAGMA user_version = 1;   -- SQL layout version (tables), separate from meta.schemaVersion (data model)
-- meta keys: schemaVersion, minReaderVersion, person, settings, onboarded, inProgressSession,
--            reviewLog, manualLog, listPrefs, pack, collections, copiedFrom, bootOkCount
```

- **No UNIQUE index on `guid`.** Duplicate detection is per target deck in the import planner (§5.6), so a GUID shared with another deck can never block an import.
- **No foreign keys or cascades.** The reducer owns relations; a cascade could delete rows the app never decided to delete.
- **Load:** `SELECT json_group_array(json(json)) AS a FROM cards` gives **one** string → one `JSON.parse` (faster than 16k parses). Same for notes. Fallback if `json_group_array` errors: `getAllAsync` + parse per row.
- **Save (`rowDiff.ts`, pure):** `diffState(lastSaved, next)` compares rows **by object identity** (the reducer never mutates). Output: upserts and deletes per table, changed meta keys, revlog inserts (reviewLog entries whose `seq` is new) and revlog deletes (entries that left the **tail** of `reviewLog` because of undo: `seq > lastSaved tail` that is missing in `next`; entries that fall off the **head** because of the 400 cap stay in `revlog`). A rating writes ≈ 4 rows: 1 card, 1 revlog, `meta.person`, `meta.reviewLog` (+ `meta.inProgressSession`).
- **`lastSaved` moves forward only after the transaction commits.** A failed save leaves `lastSaved` unchanged, so the next save retries the full diff. All saves go through one promise chain (never two at once).
- **Replace-all** (`restore`, `factoryReset`, first copy from the old storage): one transaction that `DELETE`s every table (revlog too, unless the backup carries revlog) and inserts everything. **Restore is replace, never merge.**
- **M5 stays atomic:** `sessions` insert, `meta.person` and `meta.inProgressSession = null` are always in the same transaction, because `completeSession` produces them in one reducer step and one save.
- **`revlog` queries** (`src/store/history.ts`): `historyCsv()` (sessions + revlog rows), `cardHistory(cardId)` (CardSheet "History"). Restore and backup: the backup has an optional `revlog` array; restore writes it. Size: ≈ 70 B per row, 200 reviews a day ≈ 5 MB a year.

### 3.9 The engine, store and persistence controller

```
src/store/store.ts            createStore(initial): { getState, update(fn), subscribe }   (~60 lines, no dependency)
src/store/persistController.ts PersistController(port, {debounceMs: 400, onError, now, decode})   (pure; fake timers in tests)

```

- **`PersistController` keeps every save gate:** status `'loading' | 'ready' | 'read-blocked'`. `scheduleSave` and `flush` are no-ops unless `status === 'ready' && canSave`. A load that rejects → `read-blocked` (**C1**). `flush()` before ready writes nothing (**flushSave gate**). Changes before ready are not saved (**debounce gate**). `flush()` cancels the debounce and saves now (**M16**). A failed save → `onError('write')` and the next save still tries (**M15**). `unblockAfterReset()` is the only way out of `read-blocked` (factory reset).
- **`getState()` is always current**, so actions never read a "stale by one rating" mirror. `finalCard` (M6) and the "re-read person from the latest state" rule stay in `completeSession` anyway (harmless, tested).
- **The persister subscribes to the store outside React** — no effect, no "setState in an effect" lint problem.
- **DEV deep-freeze** (`src/store/devFreeze.ts`): in `__DEV__`, `store.update` deep-freezes the new state, recursing only into objects that are not frozen yet (so the cost is the changed objects only). An in-place mutation (for example `card.flagged = true`) then throws in development instead of being silently never saved by the identity diff.
- **Round-trip test** (`src/store/roundtrip.test.ts`): for every fixture and 50 seeded random states, `load(save(state))` deep-equals `state` for the memory port, the kv port (fake) and the row port (fake db).
- **Boot reconcile (M5):** after `ready`, if `inProgressSession` is set → `completeSession(marker)` then `clearLastCompletion()` (silent). Runs once per engine. The marker carries the session's `mode` (saved with every rating since wave 5h), so the banked `SessionRecord` has a `mode` like a normal completion; an older marker without it banks exactly as before (no mode). `migrate()` keeps a valid marker `mode` and removes an invalid one (listed).

### 3.11 RKStorage rescue (Android, values over the ~2 MB read window)

AsyncStorage on Android keeps data in the SQLite file `databases/RKStorage`, table `catalystLocalStorage(key, value)` (`ReactDatabaseSupplier.java:25-32`). expo-sqlite reads TEXT with its own SQLite, not an Android `CursorWindow`, so it can read a 3 MB value. **Two SQLite libraries must not open the same live file in one process** (POSIX locks can break), so the rescue reads a **copy**:

```ts
// src/store/storage/rkRescue.ts (Android only; returns null on any failure)
const dbDir = new Directory(Paths.document.parentDirectory, 'databases');   // Paths.document = files/
const tmp = new Directory(Paths.cache, 'rk-rescue'); tmp.create({ idempotent: true, intermediates: true });
for (const name of ['RKStorage', 'RKStorage-journal', 'RKStorage-wal', 'RKStorage-shm']) {
  const f = new File(dbDir, name); if (f.exists) f.copy(new File(tmp, name));
}
const db = await openDatabaseAsync('RKStorage', undefined, tmp.uri);
const row = await db.getFirstAsync<{ value: string }>('SELECT value FROM catalystLocalStorage WHERE key = ?', 'maranki.state.v1');
await db.closeAsync(); tmp.delete();
return row?.value ?? null;
```

**Must be proven on the emulator (E2b) before release.** If it fails, the app stays read-blocked (safe).

## 4. Query model, facet engine and the one scheduler

### 4.1 One query, one evaluator (`src/domain/query.ts`, pure)

The flat `Query` type is in §3.4. It is **chip-normal**: every group is one removable chip. The search parser (§4.2) only produces flat queries. There is no OR across groups in the syntax, so **every typed token becomes a chip** — no "custom search" escape is needed.

```ts
export interface MatchCtx {
  now: number;
  index: LibraryIndex;              // §4.4
  decks: Map<Id, Deck>;
  lists: Map<string, ListDef>;      // user lists + built-in lists (§4.7)
}
export function compileQuery(q: Query, ctx: MatchCtx): (card: Card) => boolean;   // builds closures once
export function isEmptyQuery(q: Query): boolean;
export function explicitDecks(q: Query, ctx: MatchCtx): Set<Id>;                    // decks named by decks/sections (also inside a list)
```

Semantics of each group (a card matches when **all** present groups match):

| Group | Matches when |
|---|---|
| `list` | the card matches the resolved list query (one level only — a list's query may not contain `list`; `saveList` strips it) |
| `decks` | `card.deckId ∈ decks` |
| `sections` | some `s`: `card.deckId === s.deckId` and (`fold(note.section) === fold(s.path)` or it starts with `fold(s.path) + '::'`) |
| `fields` | for every key `k`: the note's folded facet values for `k` (multi-value split, §4.3) intersect the chosen values |
| `noteTypes` | `note.typeId ∈ noteTypes` |
| `directions` | `card.ord ∈ directions` |
| `tags` | some note tag `t` (folded): `t === p` or `t.startsWith(p + '::')` |
| `notTags` | no note tag matches any of them (same prefix rule) |
| `life` | `life(card) ∈ life` (§4.5) |
| `due` | `'now'`: `isDueNow(card, now)`; `'today'`: same with `due <= endOfLocalDay(now)` |
| `flags` | every flag holds: `fav`, `flagged`, `suspended`, `buried` (`buriedUntil > now`), `paused` (`deck.active === false`) |
| `notFlags` | no listed flag holds |
| `hard` / `young` / `leech` | as defined in §3.4 |
| `text` | every word (folded; a "quoted phrase" is one word) is a substring of `index.searchText(note)` |

### 4.2 Search syntax (`src/domain/searchParse.ts`, pure)

`parseSearch(input, ctx) → { query: Query; rest: string; hints: string[] }`. A token needs a word boundary before it (`hashtag:x` is plain text). Tokens repeat (`tag:b1 tag:verb` works). Everything folds accents (`uber` finds `über`).

| You type | Becomes |
|---|---|
| `haus küche` | `text: "haus küche"` (both words must match, any field, any order) |
| `"die stunde"` | phrase |
| `deck:german` or `deck:"German Verbs"` | `decks` (resolved by folded name prefix; several matches → all) |
| `section:verbs::b1` | `sections` (deck = the only Deck chip if one, else every deck that has the section) |
| `tag:algo` / `-tag:leech` | `tags` / `notTags`; a value that is not a tag is read as the last part(s) of a tag path, as the tag tree shows it (`tag:"topic alpha"` → `algo::core_patterns::topic_alpha`); no such tag → still a chip + "No tag called 'x' here." |
| `level:b1`, `type:verb`, `category:"core patterns"` | `fields[folded name]` **when a facet field with that folded name exists in scope**; otherwise the token stays text and `hints` gets "No field called 'level' here." A value no note in scope has is still a chip + "No Level 'b3' here."; `_` may stand for a space (`category:core_patterns`). |
| `is:new` `is:notstarted` `is:learning` `is:review` `is:mastered` `is:known` | `life` |
| `is:due` / `is:duetoday` | `due` |
| `is:fav` `is:flagged` `is:suspended` `is:buried` `is:paused` (and `-is:…`) | `flags` / `notFlags` |
| `is:hard` `is:young` `is:leech` | the boolean groups |
| `dir:1` (ord + 1) | `directions` |

On submit (or space after a complete token) the token **turns into a chip** and leaves the text box. `chipsOf(q, ctx): ChipModel[]` gives one chip per group with a label (`"Level: B1, B2"`, `"Deck: German"`, `"Not started"`, `"Due now"`, `"Text: haus"`) and `removeChip(q, chipId) → Query`. Tapping a chip (not its ×) opens the FacetSheet scrolled to that group.

### 4.3 The facet engine (`src/domain/facets.ts`, pure)

```ts
export type FacetKey = 'life' | 'due' | 'flags' | 'deck' | 'section' | 'noteType' | 'direction' | 'tag' | `field:${string}`;
export type OrdinalKind = 'cefr' | 'jlpt' | 'hsk' | 'numeric' | 'natural';
export interface FacetValue { value: string; label: string; count: number; selected: boolean; rank?: number; children?: FacetValue[] }
export interface Facet { key: FacetKey; label: string; kind: 'list' | 'tree'; ordinal: OrdinalKind | null;
                         values: FacetValue[]; searchable: boolean; info?: string /* "All cards here are B1." */ }
export function deriveFacets(pool: Card[], scope: Query, selection: Query, ctx: MatchCtx): Facet[];
export function detectOrdinal(labels: string[]): { kind: OrdinalKind; rank(v: string): number } | null;
export function fieldFacetSpecs(types: NoteType[], notes: Note[]): Map<string, FacetFieldSpec>;   // which fields are facets (memoized on notes)
```

**When a field is a filter group (in a scope).** Fields with the same folded **name** in different card types are **one** group (all three German card types have `Level` → one Level group). A field is a group when:
1. its `facet` override is `'on'`; **or** it is `'auto'` and, over the notes whose type has the field: **≤ 24 distinct non-empty values** (folded: HTML stripped, trimmed, lower case), **filled in ≥ 50%** of those notes, and **no value longer than 40 characters**;
2. multi-value: if the raw values have > 24 distinct values, but splitting on `,` `;` `|` gives ≤ 24 tokens and the average is > 1.2 tokens per value, it is a multi-value group (`multiSep` set) — German Verbs `Tags` (84 raw → 20 tokens);
3. in the current scope the group has **≥ 2 values with count > 0**. With exactly one value it is not a group; it becomes an **info line**, for example "All cards here are **B1**."

Rules 1–2 run **per card type** (each card type's field is a member of the group): a member that passes is in the group; a member that fails alone joins only when the union with the passing members still passes; other members are left out and **never remove the group of the other card types** (a word list with a free-text `Level` column must not remove the German Level filter). The import Preview runs the same rule on the library as it will be after the import.

On the user's real decks this rule finds exactly `Level` (4 decks), `Type` (Spanish), `Category` (Coding) and Verbs `Tags` (split). The next field has 84 raw values, then 176 — a wide safety margin (report 3).

**Structure groups:**
- `section`: a **tree** from `note.section` split on `::`; shown when the scope has ≥ 2 sections.
- `tag`: a **tree** from tags split on `::`; underscores show as spaces; a parent matches all children. A search box appears inside when > 30 tags.
- `deck`: shown when the scope has ≥ 2 decks.
- `noteType` ("Card type"): shown when the scope has ≥ 2 card types, unless equivalent (below).
- `direction`: shown when the scope has ≥ 2 ords **with different template names**; labels use the languages when known ("German → English").
- Built-in groups, always shown: **Status** (`life`: Not started · New · Learning · Review · Mastered · Known), **Due** (Due now · Due today), **Markers** (`flags`: Favorite · Flagged · Suspended · Buried · In a paused deck), plus Hard / Recent / Leech toggles.

**Equivalence collapse:** if two groups split the scoped pool into exactly the same partition, show only the higher one: field > section > noteType. One pass with a `Map` from value A to value B. Examples: Algo_Patterns `Category` == section → only "Category"; German_Complete card type == first section level → card type hidden; Spanish `Level` == section → only "Level".

**Ordinal sort (the only domain knowledge, and it is value-based):**

| Kind | All values must match | Order |
|---|---|---|
| `cefr` | `/^(pre-?)?[abc][12](\.\d)?\+?$/i` | A1 < A1.1 < A2 < B1 < B2 < C1 < C2 |
| `jlpt` | `/^n[1-5]$/i` | N5 < N4 < N3 < N2 < N1 |
| `hsk` | `/^hsk\s?[1-9]$/i` | HSK1 < … < HSK9 |
| `numeric` | every value parses as a number | numeric |
| `natural` | values share a prefix and end in a number ("Unit 2", "Lesson 12") | natural ("Unit 2" < "Unit 12") |

Otherwise: count descending, then label. Section tree levels use the same sort, so "Vocabulary › A1, A2, B1…" is in level order.

**Counts (why "No matches" cannot happen).**
- Scope = where you are (a deck, a list, "All"). Selection = the chips you added.
- Count for value `v` of group `F` = cards matching `scope ∧ text ∧ (every selected group except F) ∧ (F = v)`. This is standard disjunctive faceting: you can pick A1 **and** A2 and the other values keep useful counts.
- **One pass, not one pass per facet:** for each card in `scope ∧ text`, evaluate each selected group once. If it fails 0 groups → add the card to every group's value counts. If it fails exactly 1 group `G` → add it only to `G`'s counts. If it fails 2 or more → skip. Cost O(N × groups).
- Values with count 0 are hidden, **except a selected value**: it stays visible with "0" so it can be removed.
- Facet counts are computed **only while the FacetSheet is open** and are memoized on `(scope, selection, cards identity, index identity)`. The chip row shows no counts.
- **Budget:** ≤ 80 ms to open the FacetSheet on German_Complete with both directions (15,960 cards) on the emulator; a jest perf guard (node) asserts < 150 ms for a 16k synthetic pool. If the emulator budget fails, the fallback is already designed: counts are computed in a `setTimeout(0)` after the sheet opens, with a "Counting…" placeholder.

### 4.5 Lifecycle, eligibility and the one scheduler (`src/domain/life.ts`, `src/domain/schedule.ts`, pure)

```ts
export function life(card: Card): LifeKey {
  if (card.knownAt != null) return 'known';
  if (card.reps === 0) return card.newState === 'notStarted' ? 'notStarted' : 'new';
  if (card.stepIndex !== null) return 'learning';
  return card.intervalDays >= MASTERED_INTERVAL_DAYS ? 'mastered' : 'review';
}
export function isDueNow(card: Card, now: number): boolean;   // life ∈ {learning, review, mastered} && due <= now && studiable
export function isMastered(card: Card): boolean;              // life(card) === 'mastered'  (Known is NEVER mastered; used by achievements)
```

**Eligibility for Study** (`studyEligible(card, ctx, explicitDecks)`): the deck exists; `deck.active || explicitDecks.has(deck.id)` (**a paused deck can still be studied from its own deck page or by a query that names it** — today's `session.tsx:87-90` behaviour); the card's direction is enabled (`deck.options.directions`); not suspended; not buried.

**Buckets** (all inside `selectScheduled(pool, ctx)`; `pool` = cards matching the scope query and eligible):
1. `learn`: `life === 'learning'` and `due <= now`, by `due` ascending. Never capped by the daily limit (as today).
2. `reviews`: `life ∈ {review, mastered}` and `due <= now`, by `due` ascending, **review-sibling rule** (if two cards of one note are both due, keep the earlier one; the other waits), then capped by `max(0, dailyReviewLimit − done.reviews)`.
3. `checks`: Known cards with `knownCheckedAt == null`, deck option `knownChecks === true`, **sampled** (`hash(card.id) % 10 === 0`, a stable FNV-1a hash), and `knownAt + spreadDays(card.id) × DAY <= now` where `spreadDays(id) = 21 + (Math.floor(hash(id) / 10) % 70)` (other bits than the sample test, so the spread is even). Capped by `max(0, knownChecksPerDay − done.checks)`. *Example: marking 1,530 A1 cards Known creates ~153 checks spread over ~70 days ≈ 2 a day, never more than 5.*
4. `fresh` (`allocateNew`): candidates `life === 'new'`. **New-sibling rule** (`settings.spaceSiblings`): skip a card if a sibling has `lastReviewedAt >= startOfLocalDay(now)`, is in learning now, or is already picked; **at most one card per note per day**. Group by deck in `deck.order`; inside a deck sort by `newOrder` (`'source'`: `newPos`, then `ord`, then `id`; `'random'`: `hash(id + dayKey)`). Per-deck cap `deck.options.newPerDay − done.newByDeck[deck.id]` (null = no per-deck cap). **Round-robin**: take one card from each deck in turn while the global `dailyNewLimit − done.neww > 0`. *This fixes the "Grammar and Verbs starve behind Vocabulary" bug.*
5. **Session size** (`settings.sessionLimit`, 0 = no cap) cuts the concatenation `[...learn, ...reviews, ...checks, ...fresh]` from the end, for **every** kind.

### 5.3 Templates → directions and roles (`src/domain/roles.ts`)

`parseTemplate(qfmt, afmt, fieldNames)` collects which fields appear on which side. It does **not** run Anki's template engine.

| Tag | Meaning |
|---|---|
| `{{Field}}`, `{{{Field}}}`, `{{text:Field}}` | field shown on this side |
| `{{#Field}}…{{/Field}}`, `{{^Field}}…{{/Field}}` | conditional; collect the fields inside |
| `{{FrontSide}}` | ignored (the answer side always echoes the prompt small, as `StudyCard` does) |
| `{{tts de_DE:Word}}` | `FieldDef.lang = 'de-DE'` for `Word` |
| `{{type:Field}}` | `TemplateDef.typeField` |
| `{{cloze:Text}}` | cloze template |
| static text ("Hint:", "Conjugation") | dropped; labels come from field names (editable) |

`prompt` = fields in `qfmt` that are not badges. `answer` = fields in `afmt` not in `prompt` and not badges, in `afmt` order. CSV, manual and migrated types use synthesized templates.

*Real check:* German Verbs EN-DE `qfmt` shows `{{Meaning}}` and `Hint: {{CaseInfo}}` (up to verbs version 3 `{{{CaseInfo}}}`, which reads the same) → `prompt: [Meaning, CaseInfo]`; German Vocabulary DE-EN has `{{tts de_DE:Word}}` → `Word.lang = 'de-DE'`.

**`inferFieldRoles(type, notes)`, first matching rule wins:**
1. **Pack preset** by card-type name (German pack only, §9.4).
2. **Badge by data:** passes the facet rule (§4.3) → `badge`, `facet: 'auto'`.
3. **Pronunciation:** name matches `/pronunc|ipa|aussprache|phonetic|pinyin|reading/i`, or ≥ 60% of values look like IPA (`/…/`, `[…]`, or contain `ˈ ː ə ʃ`).
4. **Template position:** first prompt field of ord 0 → `term`; first prompt field of the reverse template → `meaning`.
5. **Name regexes** (existing `FRONT_RE`, `BACK_RE`, `EX_RE` from `anki.ts:254-256`) → `term`, `meaning`, `example`. **Several** fields may be `example`; the renderer shows every non-empty one. *This fixes the 3,652 German notes whose only example is in `MarankiExample`* (`anki.ts:340` took the first *named* field even when empty).
6. `/translation.*example|example.*(translation|english|en)$/i` → `exampleMeaning`.
7. Everything else → `detail` (labelled row, template order).

### 5.6 Duplicates and updates (by `guid`, never library-wide by front text)

Per note, in the planner, in this order:
1. **Inside the file:** a second note with the same `guid` gets a fresh guid (`m-<random>`); the preview says "{n} duplicate ids in this file were renamed."
2. **Same `guid` in the target deck** → **update**: replace fields and tags (mapped by field **name** if the source type changed), keep every card and its progress; create cards for newly enabled directions. *(2026-10)* When the file's Anki model is a **newer version** of a library card type (same model id; it keeps every field of the type by name and adds fields or directions), that card type is **upgraded in place** (`plan.ts` `upgradeNoteType`): same id, the learner's own field settings kept, the new fields with the import's roles, directions read again from the new templates; the reducer moves the values of EVERY note of the type to the new field order by name (`ImportPlan.noteTypes.upgrade`). So one deck never ends with two card types for one model, and the new fields reach the notes already in the library.
3. **Same `guid` in another deck** → `choices.elsewhere`: **"Update them where they are"** (default; keeps progress), **"Import as copies here"** (derived guids `m-<guid>~copy-<deckId>`, so a later import finds the copy again instead of adding it twice), **"Skip them"**. If every note is an update, no empty deck is created; Done says "Updated {n} cards ({u} items) in {decks}. Nothing new." (the items only when they differ from the cards: "Updated 3 cards in German.").
4. **No `guid`** (CSV without a guid column): duplicate only when the **target deck** has a note of the same card type with the same folded sort field → skip, counted as "already here". *(Wave 5g, walkthrough E8)* Because a CSV has no guid, a re-import that finds no deck by its `sourceKey` (the Android picker gives the real file name only sometimes: a pick from its recent files is a document id such as `msf:102`, so the key becomes `file:Imported deck.csv#<hash>`) starts on **"Existing deck: {the deck where at least half of the chosen rows are already here}"** (`deckPageLogic.ts` `csvHomeDeck`; the same half rule as an `.apkg` re-import by guid). Only the decks of the first plan's same-text list (rule 5) are planned again; a deck whose items only share the text but are of another card type has 0 rows already here and is never chosen. A different file that shares fewer than half of its rows still starts on "New deck". **Only when the file's name was lost on one of the two picks** (`maybeSameFile`): the pick is nameless, or the deck's key names no real file (a nameless key, an old `file:msf:96` key, no key) — in both orders of E8. **Only a deck that came from a file** (`isFileDeck`: an `.apkg` or a CSV) can be this home: a deck made in the app, a starter pack or an AnkiWeb download came from no picked file, so it is never planned again, and its shared rows are the same-text note of rule 5, with "Skip these {n}" *(wave 5h, I3)*. Two different **real** names are two files: **week2.csv**, which repeats half of the words of **week1.csv**, still starts on **"New deck: week2"** (its shared words are the same-text note of rule 5, with "Skip these {n}"). The whole start of the Preview (the learner's own choices from Fields, the guid home, this CSV step, then the first-plan changes on the deck that was chosen) is one pure step, `deckPageLogic.ts` `importStartPlan`, which `import.tsx` calls and the tests call.
5. Same headword in another deck with a different guid (German Verbs vs German Vocabulary: 475 of 682) → imported normally; the preview says once: "{n} items have the same text as items in **{deck}**. They are studied separately. [Skip these {n}]" (one: "1 item has the same text as an item in **{deck}**."). *(Wave 5g, E8)* The note says what it counts — the same **text**, not the same item — so it does not read as a contradiction of "Already in other decks: 0" (which counts the same **item**, by guid).

## 6. Study session

### 6.1 Building the queue

`session.tsx` builds its queue **once**, in the `useState` initializer (where `Date.now()` is allowed), with `buildSessionQueue(params, state, ctx)` from `scope.ts`:

| `kind` | Pool | Order and cap |
|---|---|---|
| `scheduled` | `scopePool(q, 'study')` | `planQueue(selectScheduled(...))` — learning, due reviews, checks, new; session size |
| `ahead` | `scopePool(q, 'study')` | `selectAhead` — not-yet-due reviews, soonest first; session size |
| `practice` | `scopePool(q, 'browse')` or the `sel` ids | `selectPractice(pool, sort)` (§6.6); session size |

The per-card **mode** (for `mix`) and the **quiz options** (for `mc`) are also fixed in the initializer, from a stable hash of `cardId + sessionDayKey`, so render stays pure (React Compiler).

The session keeps every current rule: the snapshot undo stack (queue, idx, counts, run, bestRun, wrote, fastAnswers), `trackSession` after every rating with `studyDay`, the `beforeRemove` partial commit, the `ratingLock` against double taps, "Again" re-queues at `idx + 3`. **New:** `rateCard` returns the rated card; the session uses it for the re-queued copy and as `finalCard` (no second `applyRating` call for scheduled kinds).

### 6.2 How a card is drawn — field roles, not fixed slots

```ts

  | { t: 'text'; text: string; b?: boolean; i?: boolean; u?: boolean; sub?: boolean; sup?: boolean }
  | { t: 'img'; src: string }
  | { t: 'sound'; src: string };
export interface FieldBlock { field: number; label: string; role: FieldRole; lines: Inline[][]; plain: string; lang?: string }
export interface CardFace {
  promptPlain: string;   // one line for rows, snackbars, a11y (replaces card.front)
  answerPlain: string;   // one line (replaces card.back)
  badges: FieldBlock[];  // pills on the top row (Level B1)
  prompt: FieldBlock[];  // question side; first = headline
  answer: FieldBlock[];  // revealed side; first = headline
}
export function htmlToLines(html: string): Inline[][];   // the safe subset
```

**Safe HTML subset** (`src/domain/htmlLines.ts`): `<br>`, `</div>`, `</p>`, `</li>`, `</tr>` → new line; `b/strong`, `i/em`, `u`, `sub`, `sup` → styles; `<img src>` → image inline; `[sound:x]` → sound token; entities decoded (reuse `anki.ts` `NAMED_ENTITIES`); `<script>`/`<style>` removed with their content; **every other tag is dropped and its text kept**. No WebView, nothing executable. Linear-time scanning (same rule as `stripHtml`, `anki.ts:224-229`). *A conjugation table `ich bin<br>du bist<br>…` now shows as lines.*

**Layout** (`StudyCard.tsx`, paper & ink tokens only):
- Top row: badges as `FacetBadge` (an ordinal CEFR-like value uses `c.cefr[value]`; others a neutral `Pill`), step label, requeued tag, 🔊.
- Prompt: first block serif 42 (40–120 characters → serif 28; longer → sans 20); other prompt blocks sans 14.5 `ink3` with their label.
- Answer: prompt echo (sans 14.5 `ink3`), hairline, first answer block serif 31; `example` serif italic 16.5 `ink2` (every non-empty example field); `exampleMeaning` sans 13 `ink3`; `pronunciation` mono 14 `ink2`; `detail` rows = `Overline` label + text with `hairlineSoft` between rows; images full width (`expo-image`, tap = full screen) on the **image well** `c.imageWell` (§8.13), light in both themes, on the card and full screen (there the well has the picture's own shape, on the opaque `paperSunk` backdrop); a missing picture keeps its quiet `paperSunk` placeholder; empty fields are skipped.
- **The card body is a `ScrollView`** (max height = screen minus header and rating zone) with a soft paper fade at the bottom when more content is below. *Long Anki backs can scroll now.*
- Term decoration (gender colours) comes from the language helper (§9.2).
- Cloze: prompt = Text with deletion k shown as "[…]" (or "[hint]"); answer = Text with deletion k in bold; Extra as a detail row.

Both now come from one function (`src/utils/dateFormatting.ts` `reviewWait`); the short and the long form differ in words, never in the number: less than 1 hour → minutes ("10m" / "in 10 minutes"); later the same local day → hours ("3h" / "in 3 hours"); else **local calendar days** ("1d" / "tomorrow", "4d" / "in 4 days"; 23:30 → 01:00 is tomorrow; DST-safe); 30 days or more → months ("2mo" / "in 2 months"); 365 days or more → years ("1.2y" / "in 1.2 years"). Due: "due" / "due now".
- *(Wave 5i)* **A tap on a picture shows it full screen**, as in a session: the shared `src/components/ui/ImageViewer.tsx` (moved out of `StudyCard.tsx`): the opaque `paperSunk` backdrop, the light `imageWell` behind the picture, **"Close image"** (✕ and a tap anywhere), and Android's Back closes the picture first (its modal is on top of the sheet's). The picture is a "Picture" image button with the hint "Shows the image full screen". Before, a tap on a picture in the sheet did nothing.

**Backup file** (`src/platform/backupFile.ts`): `{ format: 'maranki-backup', version: 1, schemaVersion, exportedAt, app: { variant, version }, data: DataState, revlog?: RevlogRow[], media?: { deckId, name, base64 }[] }`. Old exports (raw `DataState` JSON written by today's `backup.ts`) are also accepted.

**Export a backup** (Settings › Your data, Erase sheet, DataProblemScreen): build the envelope (revlog from wave 3; images when their total ≤ 50 MB and "Include images" is on) → `new File(Paths.cache, 'maranki-backup-<stamp>.json')` → `Sharing.shareAsync(uri, { mimeType: 'application/json', dialogTitle: 'Save your Maranki backup', UTI: 'public.json' })`. If `Sharing.isAvailableAsync()` is false, write to `Paths.document/backups/` and show the file name.

**Automatic backups:** after boot, when `autoBackup` is on and the newest is older than 7 days → write an envelope (no media) to `Paths.document/backups/auto-<stamp>.json`, keep the newest 3, set `lastAutoBackupAt`. Settings › Your data lists them with **"Share"** and **"Restore"**.

**File names (wave 5b):** every `<stamp>` of a file the learner sees (export, weekly backup, before-restore copy, history CSV/zip, and the rescue copy `maranki-raw-data-<stamp>.json` of "Save a copy of my data", `rescueExport.ts`) is the phone's **local** time, `YYYY-MM-DD-HH-mm-ss` (`localFileStamp` in `src/store/backup.ts`). The app reads the time back from the name to sort backups; names written before wave 5b (UTC) are read as local time too (a few hours off at most, which no 7-day or 30-day rule notices). Only the copies of corrupt data that the storage ports keep inside the app (never shown) stay in UTC (`backupStamp`).

**Restore flow** (`src/components/data/RestoreFlow.tsx`):
1. `File.pickFileAsync({ mimeTypes: ['application/json', '*/*'] })` → `canceled` → nothing.
2. `file.text()` → `decodeBackup(text)` → `migrate()` (the same function as boot).
3. Not JSON / not Maranki → snackbar **"This file is not a Maranki backup."** `too-new` → **"This backup was made by a newer version of Maranki. Update the app first."**
4. RestoreConfirmSheet: **"Restore this backup?"** · "From {12 Oct 2026, 21:04} · {3} decks · {1,240} cards · {12}-day streak." · (only for a backup without review history, when the restore writes this phone's history back) "This backup has no review history, so your current review history is kept." · **"This replaces everything on this phone. We save a backup of your current data first."** · **"Hold to restore"** (1-second press) · "Cancel".
5. Write `Paths.document/backups/before-restore-<stamp>.json` → `actions.restore(state)` (replace-all, one transaction) → write revlog and media → snackbar **"Restored — {3} decks, {1,240} cards."** A backup **without** review history (a weekly backup written before wave 5, an old export) writes the phone's **current** history back instead (`historyToKeep`, wave 5b), so a restore never empties the history without a word. The rules (review round 1): the note is decided from the history **table** when the file is reviewed (`keptHistoryCount`), not from the state's undo window (the two can differ: `migrate()` may drop a log entry whose row stays). A phone row of the **same review** (same card, same time) as a rating of the restored log is not written twice; every other phone row is kept. When a kept row's `seq` is taken by **another** rating of the restored log (a backup from another phone, or an old export whose log was numbered by the migration), the kept rows get new `seq`s after the restored log's highest, in their old order — never written over a restored row, never left out.

Old v0 backups restore too (migration handles the `word`/`tr` shape). *German-fork users: see §9.5 — the in-place upgrade is the real path, because the fork's export writes only to private storage and the fork cannot restore.*

### 8.7 Reminders (`settings/reminders.tsx`, `src/store/reminderSync.ts`, `src/platform/reminderPlan.ts`)

WHY: on Android 12 and later the reminders are **inexact** alarms (expo-notifications uses an exact alarm only with the exact-alarm permission, and Maranki does not ask for it: a study reminder does not need it); the release pass of 2026-11-02 saw a delivery window of up to one hour (`dumpsys alarm`). A single DAILY trigger cannot skip a studied day, so it is not used. (DST: dates are built from local calendar days.)
- **Sync:** `syncReminders()` cancels our scheduled requests (`getAllScheduledNotificationsAsync()` where `content.data.kind === 'maranki-reminder'` → `cancelScheduledNotificationAsync(id)`) and schedules each date with `{ type: SchedulableTriggerInputTypes.DATE, date, channelId: 'reminders' }`. Runs on: toggle/time change, app background, session complete, boot.
- **Content:** title **"Your cards are ready"**, body **"A few minutes keeps your {n}-day streak."** (n ≥ 2) or **"A few minutes today starts a new streak."**; on a day the learner **already studied** (only today's reminder, only with "Skip days when I already studied" off) the body is **"You studied today. A few more minutes helps you remember."**: the streak is already counted for that day, so it never says "starts a new streak" (release pass C1-2). `data: { kind: 'maranki-reminder' }`. No counts in the text (they would be stale). The streak of each planned day is the one still alive on that day (`streakAliveOn`, the `rollStreak` rule); "studied that day" is `person.lastStudyDay === day` (`studiedOn`).

Tap → `addNotificationResponseReceivedListener` (and `useLastNotificationResponse` for a cold start) → `router.navigate('/(tabs)')`.
- **Migration safety:** `reminderEnabled` is reset to `false` by the v2 migration and defaults to `false`, so no existing user gets a prompt or a notification without asking. Today offers it once (§8.1).

### 8.12 Accessibility (built into `src/components/ui`, so every screen gets it)

- `IconBtn` and `FAB` get a `label: string` prop → `accessibilityLabel` + `accessibilityRole="button"`. It is **optional in wave 3** (so every screen can add it while being rewritten) and **required in wave 5** (TypeScript then finds every unlabelled icon button).
- `Chip`: `accessibilityRole="button"`, `accessibilityState={{ selected }}`; its × is a separate target labelled **"Remove filter {label}"**.
- `Toggle`: `accessibilityRole="switch"`, `accessibilityState={{ checked }}`. `Stepper`: `accessibilityRole="adjustable"`, `accessibilityActions` increment/decrement, `accessibilityValue={{ text: "10 new cards per day" }}`. `SegCtrl`: the control is one `accessibilityRole="radiogroup"` named by its **required** `label` ("Default mode"; TypeScript finds a SegCtrl without one); each option is an `accessibilityRole="radio"` with `accessibilityState={{ checked }}` and its label (TalkBack: "Flashcards, radio button, checked"). WHY not `tab` + `selected`: on Android each option reached TalkBack as a plain View with no role and no state, so it never said which option was on (device pass 2026-11-02, F1-4). The options wrap onto a second row instead of cutting a label; each option is a 44 pt touch target (`hitSlop`), and two rows are 2 × that slop apart, so no slop reaches another option (`segRowGap`).
- `StudyCard`: front label **"Card. {promptPlain}. Double tap to reveal."**; back reads the prompt, the answer, then each field "Label: value". After the reveal, **when a screen reader is on**, its focus moves to the first element of the back (the prompt line), a moment after the answer appears (300 ms, `focusAfterReveal`): the view that had the focus (the front, or Typing's "Check" / a Quiz choice) is gone (release pass C1-5). With no screen reader on, nothing moves. A question with no text (only a picture) draws **no** prompt line on the back (`answerQuestionLine` is ''; an empty `accessible` Text was a silent TalkBack stop and the focus target); the focus then goes to the first element of the answer headline (its first line of text, a gender-coloured term, or its first picture). In Typing and Quiz the mode's result is drawn before the answer headline, so there the focus goes to it first: the first line of the typing result ("You typed: …") or the **picked** choice (`answerExtraFocus`, wave 5h, C2 review of wave 5g); it skipped them before. Rating buttons: **"Good. Next in 3 days."**
- Status is never colour-only: rows say the status word; `StateDot` is `accessibilityElementsHidden`. Gender colours always come with the article text.
- Heatmap, bars and SegBars have a summary label ("Studied 18 of the last 35 days"; "Level B1: 8 percent mastered").
- Touch targets ≥ 44 pt (`hitSlop` on small chips).
- **Reduce Motion:** `useReduceMotion()` (`AccessibilityInfo.isReduceMotionEnabled` + change listener, value held in `useState`, updated from the listener callback — not synchronously in the effect body) → `RiseIn` renders instantly, no pulse (and without Reduce Motion the Study pulse is finite: two breaths, §8.1), Sheet uses a fade.
- Dynamic type: font scaling allowed; tab labels `maxFontSizeMultiplier={1.3}`; Today, session and Library checked at the largest size (E9).
- Every swipe (triage) has button equivalents.

## 9. Language helpers and the German build variant

### 9.1 The principle

The data model has **no language columns** (no `level`, `type`, `lang`, `ipa` on a card). Language knowledge lives in **small, value-based helpers keyed by the BCP-47 language of a field**, switched on by **per-deck settings**. So the German features work for **any** German deck imported into the generic app, and the German build only adds content and copy.

### 9.2 Helpers (`src/domain/lang/`, pure, tested)

| File | API | Used by |
|---|---|---|
| `bcp47.ts` | `normalizeLang('de_DE' \| 'de' \| 'German') → 'de-DE'`; `primary('de-DE') → 'de'`; `langLabel('de-DE') → 'German'`; `COMMON_LANGS` (static fallback list for pickers; at runtime merged with `Speech.getAvailableVoicesAsync()` languages) | `{{tts}}` parsing, pickers, read-aloud |
| `de.ts` | `splitGermanArticle(term) → { article: 'der'\|'die'\|'das'\|null; rest: string; gender: 'm'\|'f'\|'n'\|'pl'\|null }` (case-insensitive leading article; a trailing "(Pl.)" / "(pl)" → `'pl'`; "der/die" → `null`); `germanSortKey(term) = foldText(rest)`; `isArticleQuizCard(term)` (singular der/die/das) | gender colours, A–Z sort, Typing "missing article", Articles practice |
| `index.ts` | `termHelpers(lang?: string): { sortKey(text): string; decorate(text): Segment[]; articleQuiz: boolean }` — German helpers for `primary === 'de'`, identity helpers otherwise | `TermText`, Library sort, modes |

**When a helper applies.** Only to fields with role `term`, and only when the field's **resolved language** (§6.8) has `primary === 'de'`. Gender colours also need `deck.genderColors !== false` (default true when the term language is German).

- **Gender colours** (`TermText`): the article is drawn in its colour (der `c.info`, die `c.danger`, das `c.success`, plural `c.ink3`); the rest stays ink. The article text is always visible, so colour is never the only signal.
- **A–Z by the word, not the article:** Library "A–Z" uses `termHelpers(lang).sortKey` (the fork's `browseFilter.ts:137` feature, now generic).
- **Ordinal level sort** is value-based and language-free (§4.3).
- **Read-aloud language per side:** Card type editor (per field) and the deck's ReadAloudSheet (fallback for non-Anki card types), §6.8.

### 9.3 Per-deck settings that expose the helpers (deck page)

| Row | Writes | Shown when |
|---|---|---|
| Read aloud › Front / Back (fallback for non-Anki card types) | `deck.language`, `deck.meaningLanguage` | always |
| Read aloud › per field (Anki card types) | `FieldDef.lang` via `updateNoteType` | always |
| **Noun genders (German)** | `deck.genderColors` | a term field resolves to German |
| More ways to study › **Practice articles · {n}** | (session param `mode=article`, kind practice) | ≥ 4 article-quiz cards in scope |

### 9.5 Moving German-fork users, and the signing-key rule

- The fork's package is `com.omrylmz.marankide`, the same as the German variant, and its data is v0-shape + `studyDay` under the same AsyncStorage key — `migrate()` handles it (fixture `v0-german-fork.json`). **The real path is an in-place upgrade (`adb install -r`).** "Export → Restore" is not a path for fork users: the fork's export writes only to private storage, has no share sheet, and the fork has no restore.
- **The first German variant build must be signed with the same key as the installed fork build**, or Android refuses the upgrade, and uninstalling deletes the data. Steps (in `RELEASING.md`): 1) `apksigner verify --print-certs` on the installed fork APK (`adb shell pm path com.omrylmz.marankide` + `adb pull`); 2) build the variant with that key (for a local `expo run:android` build this is the prebuild template `android/app/debug.keystore` or `~/.android/debug.keystore`); 3) `adb install -r`, run E12; 4) only after the variant has real **Export + Share** (it does, from wave 2) may the key change — export first, then reinstall and restore.
- **Never change the signing key of `com.omrylmz.maranki`** (CI falls back to the template debug key when `ANDROID_KEYSTORE_BASE64` is missing; the public v2.0.2 APK was signed by CI). A release keystore may be adopted only after v2.2.0 (export + restore) has shipped, with a notice to export first (Decision D7).
- Default policy is **roll forward**: Android will not install a lower `versionCode`, and CI uses the run number.
- After the variant passes E12 and one week of use, archive the old fork on GitHub (read-only). Do not delete it.

## 10. Work breakdown in waves

### 10.1 Rules for every wave

1. **Units inside one wave own disjoint files.** A file is owned by at most one unit per wave. "(delete)" means the unit deletes it.
2. **A unit depends only on earlier waves.** Everything a unit needs from another unit (types, action names, component props) is **pinned in this spec** and, where it is code, it was created in an earlier wave (W0-2 lays down all types). Wave 4 is the one exception: its screens open each other's sheets by the props pinned in §2–§8, so wave 4 has a **merge order** (§10.7).
3. **Done means:** the unit's new jest tests pass; `npm run verify` (= deck-file check, `npx tsc --noEmit`, `npx expo lint`, `npx jest`) is green on the merged result; no new lint suppression; React Compiler rules kept (`useNow()` in render, seeded shuffles, `useState(() => new Animated.Value())`, no synchronous `setState` in an effect).
4. **Emulator checks** (§11) listed in a unit's acceptance are run before the wave's release.
5. **Size:** one engineer, one sitting (a few days at most). For a solo developer with Claude, units of one wave can run one after another; the order inside a wave does not matter except in wave 4. Rough solo calendar: W0 2 days, W1 1 week, W2 2 weeks, W3 2–3 weeks, W4 3 weeks, W5 1 week.

### 12.2 Risks and mitigations

| Risk | Mitigation |

| A migration bug damages real data | Real fixtures from real builds; lossless `legacy` copies; pre-migration files; copy-forward without deleting sources; a throwing migration blocks writes (C1) instead of seeding; restore uses the same `migrate()`; E1 every data wave. |
| The row store is new code on the most critical path (C1, M5) | Pure `rowDiff` + small I/O; `lastSaved` moves only after commit; serial save queue; replace-all for restore; round-trip and kill/reboot integration tests; separate DB file from the kv store. |
| An in-place mutation is silently never saved by the identity diff | `devFreeze` throws in development; round-trip equality tests. |
| RKStorage rescue path differs on a real phone | Reads a **copy** in the cache; any failure stays read-blocked (safe); proven in E2b. |
| Facet counts too slow at 16k cards | One-pass algorithm; computed only while the sheet is open; node perf guard; emulator budget with a defined fallback (deferred counting). |
| Reverse cards double the daily load | Directions are visible in the import preview; "Let me choose" default for big imports; new-sibling spacing; per-deck caps; round-robin. |
| Role inference guesses wrong | Fields are never thrown away; Fields step before writing; Card type editor after. |
| Metro variant alias picks the wrong pack | W0-1 spike; clean CI builds; runtime `pack.id === extra.variant` check; `--clear` documented. |
| Notifications delayed by battery optimisation | Honest Help text; no exact-alarm promise. |
| Same-wave UI units in wave 4 depend on each other's sheets | Props pinned in this spec; explicit merge order (§10.7). |

### 12.3 Rejected alternatives (and why)

- **A deck tree (Anki subdecks as decks).** Real decks use the path as a category (level), not as a place with settings; a tree adds more "where do I study?" places. Sections are a filter instead, and export can rebuild `Deck::Section`.
- **A general and/or/not query tree.** It cannot always be shown as removable chips, which breaks "visible scope". The flat Query covers every search token.
- **`front`/`back` stored or "materialized but required" on cards.** It can go stale and creates `undefined` crashes for cards built elsewhere. Faces are rendered from notes.
- **Removing `Card.deckId` / numeric flags.** Wide churn for little value; `deckId` stays authoritative on cards, `flagged` stays boolean with an optional colour.
- **"First direction only" for big decks.** It hides the EN→DE production cards German learners most need. "Let me choose" controls the load instead.
- **"Mark as known" = a 21-day interval.** That is the old fake "Learned" write: it inflates Mastered and achievements and floods reviews later. Known is its own state with sampled checks.
- **Suspend as "not now".** It overloads Suspend; Not started is its own state with its own triage screen.
- **One repeating DAILY notification.** It cannot skip a day already studied; 14 one-shot DATE notifications can.
- **Library-wide duplicate check by front text.** It dropped 70% of German Verbs; guid + per-deck rules replace it.
- **A UI-feature flag for the new IA (`newIa`).** Old screens keep compiling through facades and are replaced once in wave 4; no double build.
- **Guessing part of speech in app code.** It cannot be done reliably; fix the data instead (D9).
- **SQL-side filtering.** Two matching implementations would drift; SQL only saves and loads.
